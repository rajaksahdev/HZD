# QC report: fault detection on injected faults

Generated by `python -m pipelines.anomaly --start 2025-06-15 --end 2025-08-31`. Do not edit by hand.

## What was tested

- **Detector:** Isolation Forest (200 trees) on seven features of each hourly reading: second difference, deviation from the median of the previous 6 hours, deviation from the usual value for that hour of day, deviation from a reference (the other grid cells at the same hour; for sea level, the same series 25 hours earlier), the 24-hour mean of that deviation, the 6-hour standard deviation, and hours since the value last changed. Every feature uses past values only.
- **Data:** hourly ECMWF forecast at the 30 pilot grid cells and hourly sea level, 2025-06-15 to 2025-08-31. These stand in for station feeds, which the project does not have yet. Rain is not tested: it is zero most hours, so a flat line is normal.
- **Split:** by time. The first 70% of hours train the detector; faults are injected only into the rest.
- **Threshold:** set so that 1% of clean training readings are flagged.
- **Faults:** 60 events per row, each at a random series and hour, random sign. Sizes are in standard deviations (sigma) of the variable around its usual daily cycle. A spike is one reading; a flat line repeats the previous reading; a drift is a straight ramp reaching the stated size after 48 hours.
- **Caught** means at least one reading inside the fault was flagged. Delay is the median number of hours from the start of the fault to the first flag.
- **No-fault rate** is how often the same window had a flag before the fault was injected. A long window can contain a false alarm by chance, so a detection rate is only meaningful where it is well above this number.

## Limits

- The faults are synthetic and the series are model output, which is smoother than a real sensor. Expect lower detection and more false alarms on real station data.
- The test period is a few weeks of one monsoon season.
- A flagged reading is only marked as suspect. Nothing is deleted.
